# Git Setup and Knowledge Reflection

**Have you used Git before? If so, in what context?**
Yes, I have used Git previously for academic projects in my systems engineering coursework and for personal development projects, such as building a point-of-sale and invoicing application. I use it to maintain version control, track my progress, and ensure I can safely experiment without losing stable code.

**Which Git client (if any) did you choose? Why?**
I have chosen to primarily use the **Git CLI (Command Line Interface)** directly within the integrated terminal of VS Code, complemented occasionally by VS Code's native Source Control UI. I prefer the CLI for executing exact commands (like creating branches, committing, and pushing) because it builds strong muscle memory and provides full control, while the visual UI is helpful for quickly reviewing file diffs before staging.

**What was the most interesting thing you learned about Git today?**
The most interesting aspect is realizing how lightweight branches actually are. Instead of duplicating the entire codebase, a Git branch is simply a movable pointer to a specific commit. This makes branching and context-switching incredibly fast, which perfectly supports the "one branch per issue" workflow I am executing for this onboarding process.
